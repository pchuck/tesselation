## Delegation rules
- Prefer `fast-worker` for discrete small tasks with clear tests or well-defined output.
- Prefer `worker` for most development iterations.
- If a worker fails twice, summarize the failure and call `strong-worker`.
- If `strong-worker` doesn't resolve it after a few tries, call `frontier` with the failing output and what was tried.
- Use `frontier` for the most challenging tasks, or when other workers aren't converging on a solution.
- **One job per agent at a time.** Each agent session is dispatched exactly one job at a time — never give a busy agent a second job, never multiplex tasks within one session. Launch one job at a time and confirm it is established, then decide on the next dispatch; never batch multiple launches.
- **Tier parallelism — one job per tier:** all four tiers run on separate hardware and work in **parallel**, but each tier carries **exactly one in-flight job at a time** — at most four concurrent jobs: 1x `worker` + 1x `fast-worker` + 1x `strong-worker` + 1x `frontier`. Never dispatch a second job to a tier whose current job is still running (regardless of task size); the tier's next job waits until its current one lands and is integrated.
- **Keep idle tiers fed.** When a tier has **no** in-flight job and dependency-free work is in the queue, dispatch to it — match the task's difficulty to the tier (fast-worker: discrete/mechanical; worker: standard; strong-worker: hard geometry/correctness; frontier: novel derivation). Work whose inputs depend on an in-flight job stays queued until that job lands.
- Briefs must be self-contained: goal, files, constraints, how to verify.

## Harness discipline
- **Persistent scratch:** `/workspace/tmp` is the shared persistent scratch location — it survives reboots and infrastructure restarts. `/tmp/opencode` is fast ephemeral scratch and can be wiped at any time. Write batteries, pinned derivations, and salvage files directly to `/workspace/tmp` (or checkpoint them there from `/tmp/opencode` before reporting). Never treat `/tmp/opencode` as the only copy of hard-won work.
- **Launch every subagent with `background: true`.** Foreground launches block the whole session; the launch receipt's "working in the background" line is boilerplate, not the mode — the parameter is what counts.
- **Background jobs notify on completion** — after launching background subagents, end the turn; the harness wakes the session as each job finishes, and integration proceeds then. Do not poll the session DB with sleep loops.
- **Vision policy (two-tier):** model vision is allowed for reconnaissance — comparing a render against a reference figure, catching gross structural errors early, UI appearance judgment — but never as verification evidence: every count, closure, pairing, or correctness claim in a report or test must be programmatic (parsed SVG/path data, exact arithmetic, census battery, mutation-checked headless test). When a visual look motivated a change, the report must cite the programmatic check that confirmed it. "Looks right" is not a deliverable.

## GUI tooling
- **Launch and drive native GUI apps, then verify.** The host runs X11 (`DISPLAY=:0`, Xorg, 2560×1440). `gui-tools/` in the repo root holds user-level binaries (no root needed): `xdotool` (synthetic mouse/keyboard input, window activate/focus/kill), `wmctrl` (window management), `xterm` (isolated scratch terminal — never type into the user's running sessions), plus `lib/libxdo.so.3`. `bin/` and `lib/` are git-ignored unpacked debs; if missing, restore per `gui-tools/README.md`.
- **Usage:** `gui-tools/xdotool <args>` (wrapper sets `LD_LIBRARY_PATH`); `gui-tools/bin/wmctrl` and `gui-tools/bin/xterm` run as-is. Screenshots: `import -window root /tmp/opencode/shot.png` (ImageMagick, system-wide) or `import -window <WINID> ...`, then read the PNG back to inspect it. Web UIs: prefer the built-in browser tools (click, fill, element screenshots, console/network logs).
- **Verified input pattern** (XTEST, not `type --window` — XSendEvent targeting was unreliable on xterm frames): `xterm -T PROBE -e 'read l; echo "$l" > /tmp/out.txt' &` → `xdotool search --name PROBE` → `windowactivate --sync $W` → `type` + `key Return` → `cat /tmp/out.txt`.
- **Caveats:** synthetic input shares the pointer/keyboard with the user's physical devices — keep move/act/verify tight and expect concurrent mouse movement. X11 only, no Wayland. Always `windowkill` scratch windows when done. A screenshot motivates; only programmatic checks (file contents, parsed DOM/SVG, pixel diffs) confirm — same two-tier rule as the vision policy above.
